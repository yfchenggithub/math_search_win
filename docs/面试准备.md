# 面试准备：高中数学二级结论搜索系统

## 1. 项目一句话介绍

> 一个基于 Qt6/C++17 的 Windows 本地离线桌面应用，实现高中数学公式的毫秒级全文搜索与 LaTeX 渲染，采用 DDD 分层架构，包含搜索算法引擎、多模态详情渲染、授权系统、自动化测试（15 个 CTest 用例）和完整发布流水线。

---

## 2. 项目故事线（面试 2 分钟版本）

**背景**：高中数学有大量"二级结论"（约 800+ 条），学生/老师需要在 3 秒内精准找到某条结论。现有方案要么是在线题库（广告多、搜索慢），要么是 PDF 文档（只能 Ctrl+F 逐字匹配）。

**我的方案**：
- 自建搜索索引（term 倒排 + prefix 前缀树），实现毫秒级模糊匹配
- Qt6 Widgets 做桌面 UI，QWebEngineView + 本地 KaTeX 做数学公式渲染
- 完全离线运行，所有数据本地加载，无网络依赖
- 支持 PDF 详情、收藏、搜索历史、授权激活等完整功能

**技术亮点**：
- 分层架构（UI → Service → Repository → Infrastructure），模块边界清晰
- 自定义搜索算法（term + prefix 双索引命中，意图交叉增强评分）
- 建议系统（三重候选来源 + 质量门控）
- 四种详情渲染路径（PDF / Web KaTeX / 文本回退 / 体验预览）
- 15 个自动化测试用例，覆盖搜索/建议/持久化/授权/详情渲染

## 3. 架构讲解（面试核心环节）

### 3.1 分层架构图

```
┌─────────────────────────────────────────────┐
│  UI 层 (Qt Widgets)                         │
│  MainWindow → 6 Pages (Home/Search/…)       │
│  Detail渲染 (WebEngine / PDF / Fallback)     │
├─────────────────────────────────────────────┤
│  领域服务层 (Domain Services)                │
│  SearchService / SuggestService             │
│  FeatureGate / LicenseService               │
├─────────────────────────────────────────────┤
│  数据仓储层 (Repositories)                   │
│  IndexRepo / ContentRepo / FavoritesRepo    │
│  HistoryRepo / SettingsRepo                 │
├─────────────────────────────────────────────┤
│  基础设施层 (Infrastructure)                 │
│  JSON Loaders / LocalStorage(QSaveFile)     │
│  Logger / AppPaths                          │
└─────────────────────────────────────────────┘
```

### 3.2 关键设计决策

| 决策 | 方案 | 原因 |
|------|------|------|
| 数据存储 | 静态 JSON 文件加载到内存 | 数据量 ~5MB，全内存搜索最快，离线无依赖 |
| 搜索算法 | 自建 term + prefix 双索引 | SQLite FTS 不支持中文分词和数学符号匹配 |
| 公式渲染 | QWebEngineView + 本地 KaTeX | KaTeX 渲染速度远快于 MathJax，本地部署无需 CDN |
| 详情首选 | PDF (QPdfView) 优先，Web 回退 | PDF 翻页/缩放体验好；Web 模式做 math 渲染 |
| 原子写盘 | QSaveFile | 防止写盘中断导致 JSON 文件损坏 |
| 页面切换 | QStackedWidget | 6 个页面以内，不需要 QTabWidget 的灵活性 |
| 跨页通信 | Qt Signal/Slot | 不引入第三方状态管理，利用 Qt 原生机制 |

### 4.3 搜索算法核心（面试加分项）

```
search("柯西不等式") 流程：
1. 查询归一化 → normalizeQueryText()
2. term 索引查找 → 精确匹配标题/别名
3. prefix 索引查找 → 前缀匹配（"柯西" → "柯西不等式"）
4. fieldMask 加权 → intent 字段匹配加 intent 分
5. 交叉增强 → 同一 doc 同时命中 intent + title 时追加加分
6. module 过滤 + 排序 → 相关度/标题/难度
7. 体验版数量裁剪 → kTrialPreviewLimit
```

**为什么不用 SQLite FTS？**
- 数学符号（±, ∈, √）分词困难
- FTS5 中文分词需要额外插件
- 全内存倒排索引搜索更快，数据量仅 ~5MB

### 4.4 建议系统算法

```
suggest("对数") 的三重候选来源：
1. 人工种子索引 → 预置的优质建议词条
2. domain/topic 层级扩展 → "对数" → "对数函数" → "对数运算"
3. prefix/term 回退 → 遍历前缀树/倒排取前 N 个
   ↓
质量门控：
  - 过滤未闭合括号的半截词
  - 过滤语义截断前缀（"柯西不等" 被 "柯西不等式" 覆盖）
   ↓
评分 → 排序 → 去重 → 返回 Top 8
```

## 6. 常见面试问题 & 准备答案

### Q1: 为什么选择 Qt 而不是 Electron？

**答**：几个核心原因——
- **性能**：Qt C++ 原生性能，启动快（< 1 秒），内存占用低（~80MB vs Electron 200MB+）
- **打包体积**：Release 打包 ~80MB（含 Qt DLL），Electron 至少 150MB+
- **离线友好**：不需要内嵌 Chromium，可以用系统 WebEngine
- **招聘需求**：目标岗位就是 Qt/C++，正好展示相关能力
- **局限性**：跨平台 UI 一致性不如 Electron，但目标就是 Windows

### Q2: 搜索算法怎么做的？为什么不用 Elasticsearch 之类？

**答**：
- 自建了 term 倒排索引 + prefix 前缀树双索引
- 支持 fieldMask 字段加权（标题/别名/intent/关键词）
- 交叉增强机制（同一 doc 多字段命中时加分）
- 不用 ES 因为：本地离线应用，数据只有 800+ 条，引入 ES 是杀鸡用牛刀，全内存搜索够快够简单

### Q3: 项目中遇到的最大挑战是什么？

**答**（选一个详细展开）：
1. **详情渲染的多路径回退** — PDF/Web/文本三种模式要在"自动"策略下智能切换，涉及 QPdfView、QWebEngineView、QTextBrowser 三套 UI 的协调和状态管理
2. **搜索建议的质量门控** — 前缀回退容易产生脏候选（如"柯西不等"这样的半截词），通过括号闭合检测 + 语义截断过滤解决
3. **跨页面状态一致性** — 收藏/历史变更需要联动 4 个页面刷新，用 Signal/Slot 实现了松耦合的跨页通信

### Q4: SearchPage 为什么这么重？你会怎么改进？

**答**：
- 现状：SearchPage 确实职责过多（搜索 + 建议 + 详情 + 收藏 + 历史 + 设置 + 性能埋点）
- 改进方案：拆分为——
  - `SearchController`（搜索/建议编排）
  - `DetailController`（详情渲染编排）
  - `SearchStateModel`（状态管理）
  - 保留 SearchPage 作为薄壳组装层
- 已在技术文档中记录了这项技术债，下一迭代优先级最高

### Q5: QWebEngineView 有什么坑？

**答**：
- **加载时序**：`load()` 和 `page()` 的 ready 信号异步，需要用标志位 + 队列机制确保 dispatch 发生在 shell 就绪之后
- **缓存路径**：必须在 QApplication 创建后、任何 WebEngine 使用前设置 `QWebEngineProfile::defaultProfile()->setCachePath()`
- **console 消息**：重写 `QWebEnginePage::javaScriptConsoleMessage()` 来捕获 JS 侧日志
- **进程分离**：QtWebEngineProcess.exe 是独立进程，打包时必须用 windeployqt 带上

### Q6: 授权系统怎么设计的？安全性如何？

**答**：
- 激活码格式：`MSW1.<base64url-payload>.<crc32-checksum>`
- 包含：产品 ID、设备指纹绑定、过期时间、功能列表
- 状态机：Missing → Trial → ValidFull → Expired → Invalid
- FeatureGate 将授权状态映射为功能开关（5 个维度：搜索预览/全文搜索/完整详情/收藏/高级筛选）
- **当前局限**：签名验证和加密是 TODO stub，生产环境需要接入 Ed25519/ECDSA 签名

### Q7: 编译/打包流程？发布怎么做的？

**答**：
- CMake 3.21+ + MSVC 2026 + Qt 6.11.0
- CMake Preset 管理 debug/release 配置
- 发布用 `release_tool.py` 脚本：
  - `cmake --build --preset msvc-release`
  - `windeployqt` 自动拉 Qt DLL 和 WebEngine 资源
  - 复制 `data/`, `app_resources/`, `license/`
  - 验证关键文件完整性
- WIN32_EXECUTABLE 属性确保 Release 双击无控制台窗口

- "收藏筛选功能预留了 UI 位置但未实现，明确标注'即将支持'保证诚实"

## 10. 改进方向（面试官问"如果重来一次"）

1. **SearchPage 拆分**：按查询编排 / 详情编排 / 状态管理拆为 3 个组件
2. **详情渲染统一**：PDF 和 Web 两条路径合并为一个抽象 RenderStrategy 接口
3. **设置页完善**：从只读状态展示变为真正可编辑的设置中心
4. **引入 Model/View**：搜索结果列表可以考虑 QAbstractListModel + QListView
5. **性能监控面板**：在开发模式下展示 FPS、内存、搜索耗时等实时指标
6. **CI/CD**：接入 GitHub Actions 自动化构建 + 测试 + 打包
